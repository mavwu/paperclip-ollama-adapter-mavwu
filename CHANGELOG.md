# Release notes

## 2.0.0 — local release candidate, 6 November 2026

This version is prepared for independent review and has not been published. The registry's latest release at preparation time is 1.0.10, published 28 June 2026. The comparison below uses that downloaded npm artifact, whose recorded source revision is `c46df60c9c54502ae427f955740c9a8d474562a7`, rather than assuming the package matches a local Git tag. Candidate source baseline: `ae810311fc6f6eee761a5317d239ce1842a1ba13`. No runtime feature is added by release preparation; the existing safety work is being documented and packaged.

### What users gain

- Real text inference is verified: the Mavwu root factory executed `qwen2.5-coder:1.5b` through Ollama's actual OpenAI-compatible HTTP transport and returned the provider's final `42` answer. The [smoke report](docs/phase-2-live-inference-smoke.md) records real missing-model, cancellation and timeout outcomes and their limits. No full Paperclip host or production issue was involved.
- Results distinguish text received, verified delegation, failure, cancellation and timeout. Required action failures cannot masquerade as successful chat. Empty, refused, truncated, reasoning-only and unsupported tool-call responses fail explicitly.
- Trusted configuration layers, strict endpoint/credential checks, separate direct HTTP clients, bounded diagnostics and secret redaction reduce accidental credential and destination exposure.
- Cooperative host cancellation and bounded model, Paperclip and overall deadlines stop subsequent work, abort local HTTP requests and preserve already-observed creation receipts.
- Durable delegation code reserves one logical slot per source issue and reconciles authoritative receipts. It is disabled by default and is not approved for production activation.
- The package includes this migration guide, the configuration reference and the two public investigation reports. Raw traces, credentials, machine-specific plans, test fixtures, caches and runtime skills are excluded.

### Breaking changes and migration from 1.0.10

| Previous published behavior | 2.0.0 behavior | Required migration |
| --- | --- | --- |
| Successful replies could automatically PATCH an issue to `done`; `AUTO_MARK_DONE` defaulted to true. | No automatic completion writes occur, even when the deprecated setting is true. `workflowCompleted` is always false. | Provide an external disposition/review/continuation workflow. Account for host missing-disposition recovery; do not enable auto-completion to suppress it. |
| `stopReason: "completed"` could describe a generated reply or an unsuccessful organizational action. | Use `response_received`, `delegated`, `failed`, `cancelled` or `timed_out`; required failures return nonzero `exitCode` and `success: false`. | Update result consumers and retry logic. Text receipt and follow-up creation do not establish source-task completion. |
| Reasoning fields or responses containing structured tool calls could be accepted as final output. | Reasoning-only, empty, truncated, refused and structured tool/function-call responses fail validation. | Use a model that returns usable final text and an adequate token limit. Ordinary text is not proof of tool execution; no tool executor is provided. |
| Permissive configuration could silently trim/fall back, coerce values and mix alias/environment precedence. | Explicit config > host-resolved `config.env` > process environment > defaults; uppercase wins within each layer. Invalid selected values fail before network activity. Only temperature and token limits accept task options. | Remove invalid/blank optional endpoint overrides. Audit duplicate aliases and move model, credentials, destinations and deadlines into trusted configuration. See the [exact contract](CONFIGURATION.md#fields). |
| Arbitrary HTTP endpoints, redirects, ambient proxies and Axios defaults were not bounded by the current isolation policy. | HTTP is loopback-only; remote endpoints require HTTPS. Embedded URL credentials, query/fragment/whitespace and malformed URLs are rejected. All redirects and ambient proxies are disabled. | Use direct loopback HTTP or trusted remote HTTPS with valid certificates. A non-redirecting trusted gateway may replace a required proxy setup. |
| Credentials could be trimmed and environment identity fallbacks were permissive. | Supplied bearer credentials must be visible ASCII without whitespace and are never repaired. Paperclip identity comes only from host `context.authToken`; a process/agent `PAPERCLIP_API_KEY` cannot authorize it. | Correct credential values at the source. Omit `API_KEY` for Ollama's public placeholder; an explicit empty key disables model Authorization, and an explicit `ollama` key is treated as secret. |
| Delegation could create follow-ups without the current durable safety contract and strict assignee resolution. | Writes require `DELEGATION_STORAGE=paperclip_documents_v1`, verified ownership/work mode, one create-only reservation and authoritative receipt verification. Default is `disabled`. Assignees use exact eligible matches; ambiguous/self/ineligible assignments fail. | **Keep storage disabled in production.** Reconcile old attempts, validate/fix the intended host and establish the durable contract before any future opt-in. Never delete records or blindly replay uncertain writes. |
| Inference had a fixed request timeout and no overall cooperative lifecycle contract. | Defaults: model 120000 ms, Paperclip 30000 ms, overall 300000 ms. Positive trusted `timeoutSec` can further cap the run. Millisecond deadlines must be positive integers <=86400000. | Long-running installations may need explicit trusted budgets. Zero cannot disable these deadlines; task options cannot extend them. |
| The package advertised `paperclipPlugin.manifest` and an npm/upload general-plugin flow. | That invalid current-plugin declaration is removed. The external-adapter installer imports the root `createServerAdapter()`; `./manifest` is retained as legacy metadata. | Use your verified host's external-adapter route with a published package or built absolute local path. General plugin upload is unsupported. Until publication, use this candidate's reviewed tarball for consumer verification or the built local checkout for host installation. |
| Node `>=18.0.0` was advertised without a complete minimum-runtime validation. | This candidate supports `>=24.11.1 <25`; the complete suite is verified on Windows 24.11.1. | Upgrade to the supported Node 24 line, or defer adoption until your runtime is independently validated. See the runtime policy below. |
| `npm test` required live Ollama. | `npm test` builds and runs 484 deterministic regressions. Live inference is a separate opt-in source-checkout `npm run test:integration`. | Update CI to run the deterministic suite; run live checks only in an explicitly configured test environment. |

The published README claimed hiring support, but the downloaded 1.0.10 execution artifact contains no verified hiring implementation. This release corrects that claim: it does not create/hire agents or handle approvals. This is a documentation correction, not a newly removed working hiring feature.

Root exports remain `type`, `label`, `models`, `agentConfigurationDoc` and `createServerAdapter`; `./server` and legacy `./manifest` remain available. The package stays ESM-only. The factory exposes `execute`, `testEnvironment`, `getConfigSchema`, metadata and `supportsLocalAgentJwt: true`. No new native tool API or autonomous runtime is introduced.

### Runtime compatibility

The tested dependency graph is locked: adapter-utils 2026.609.0, Axios 1.18.0, dotenv 16.6.1, TypeScript 6.0.3 and Node types 24.13.2. Release preparation changes no dependency ranges or locked resolutions. TypeScript emits ES2022, and the installed dependencies do not declare a Node 24 floor. These facts alone do not establish that all security/lifecycle behavior works on every Node >=18 release.

Official portable Node 18.0.0 was checksum-verified and tested. No-emit compilation and package-root import pass; the unchanged full suite cannot run because this minimum lacks `--test`, and its older `node:test` API lacks the current hooks/mocking contract. Targeted real-loopback inference/lifecycle probes are additional evidence, not full regression certification. The conservative supported range is therefore `>=24.11.1 <25`, with Windows 24.11.1 verified. Node 18 is [end of life](https://nodejs.org/en/about/previous-releases). Other Node majors and operating systems are unverified for this candidate; expand the matrix before expanding the engine declaration. This is a validated support policy, not evidence that the adapter cannot import on older Node with the older locked dependencies.

A clean npm consumer install of the candidate under the unchanged dependency ranges resolved **adapter-utils 2026.1023.0**, **Axios 1.21.0** and **dotenv 16.6.1**. adapter-utils 2026.1023.0 and its `@paperclipai/shared` dependency declare **Node >=24.11.0**; their bundled CLI dependencies also remain within the candidate's Node 24 range. Thus the old blanket Node >=18 claim is incompatible with the currently resolved installation graph, even though the older source lockfile can pass limited Node 18 probes. All **484 regressions passed against the installed tarball with this fresh graph**, in addition to passing from a clean `npm ci` source build. Public root, server and legacy-manifest imports passed with lifecycle scripts disabled. Resolving these dependencies does not launch their bundled coding-agent CLI or make this adapter a tool runtime.

The source lockfile is not installed by npm consumers; the existing caret ranges permit later compatible releases. Retain a consumer lockfile for repeatable deployments and recheck actual versions, engines and regressions immediately before publication/rollout. No dependency range or source lockfile resolution was changed to obtain these results.

The installed adapter-utils 2026.609.0 types predate optional `signal`, `onCancellationReady` and `onDispatch` fields. Cancellation requires a host that actually supplies the supported structural lifecycle contract. The tested isolated Paperclip server build 2026.1023.0 is not assumed interchangeable with that June type package or a different pinned source checkout. Actual host installation, scheduler, checkout, missing-disposition recovery and retry behavior still need independent integration review.

### Delegation restrictions and truthful outcomes

**Production delegation remains blocked.** In the exercised Paperclip 2026.1023.0 build (`1b4c803816e82b0265c8422e1a804327a7ed8c54`) with disposable PostgreSQL 18.2 and real HTTP routes, child creation accepted stale ownership after final adapter GET checks. Concurrent document creation also produced PostgreSQL deadlocks/HTTP 500 responses despite one authoritative reservation row. Ownership checks must be atomic with the server write, and lock-order/error handling must be fixed and retested against the intended deployment. More client reads and blind retries do not solve either defect. See the [full bounded findings](docs/phase-1-integration-findings-and-phase-2-poc.md).

Cancellation is cooperative. Aborting Axios locally does not prove Ollama stopped computing or that a remote write rolled back. Already-observed creation IDs remain evidence even if later persistence or callbacks fail. Unknown creation outcomes require authoritative reconciliation; neither a timeout nor an expired idempotency key authorizes replay. Host callbacks and blocked JavaScript can delay settling beyond the nominal deadline.

The adapter provides one-shot text inference and limited company operations. It has no filesystem or shell tools, tool execution loop, agent-hiring/approval implementation, runtime skill delivery, restored conversation history or verified task-completion mechanism. Model selection lists are conveniences, not capability certifications. The earlier coding-agent experiments did not demonstrate a working coding-agent runtime; the later text-only smoke passed. Neither model prose nor process exit zero is proof that tools ran or a source task was completed.
